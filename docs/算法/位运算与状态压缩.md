# 位运算与状态压缩

把整数的二进制位当作集合来用的那一套惯用法。先立约定，再记工具，最后是两个用它们秒杀的例题。

## 1. 核心约定：整数即集合

只有一条规则：

> 第 `i` 位是 1 ⟺ 元素 `i` 属于这个集合。

于是集合 `{2, 3, 5}` 写作 `0b101100`。一旦接受这个约定，位运算就全是集合运算：

| 集合语义 | 位运算 |
| --- | --- |
| 添加元素 `i` | `s \| (1 << i)` |
| 删除元素 `i` | `s & ~(1 << i)` |
| 判断 `i` 是否在集合中 | `(s >> i) & 1` |
| 并集 | `a \| b` |
| 交集 | `a & b` |
| 差集 | `a & ~b` |
| 子集判断 `S ⊆ T` | `a & b == a` |
| 空集 | `s == 0` |

之所以要这样绕，是因为整数位运算比维护 `set` 快得多，而且能整体塞进 DP 下标（`dp[mask]`）——这就是状态压缩。

## 2. 三个内置工具

| Python | 二进制视角 | 集合视角 |
| --- | --- | --- |
| `n.bit_count()` | 1 的个数 | 集合大小 `len(S)` |
| `n.bit_length() - 1` | 最高位 1 的下标 | 最大元素 `max(S)` |
| 尾零个数 | 最低位 1 的下标 | 最小元素 `min(S)` |

三个要点：

- **`bit_length()` 为什么要减一**：它数的是「占了多少位」，从 1 开始数；元素编号从 0 开始。`0b101100` 占 6 位，最大元素是 5。
- **`bit_count()` 需要 Python 3.10+**；旧版本用 `bin(n).count("1")`。
- **尾零没有内置函数**，标准替代写法是 `(n & -n).bit_length() - 1`（见下一节）。

以 `n = 0b101100`（集合 `{2, 3, 5}`）为例：

```python
n.bit_count()                # 3  → |S|
n.bit_length() - 1           # 5  → max(S)
(n & -n).bit_length() - 1    # 2  → min(S)
```

## 3. lowbit：`n & -n`

只保留最低位的那个 1，其余清零。Python 的负数是无限位补码，`-4` 写作 `...111111100`：

```
  4 = 0b000000100
 -4 = 0b111111100
 &  = 0b000000100   = 4
```

低位部分只在最低那个 1 上重合，更高位全被 `~n` 抹掉。结果是 `2**i` 这种 2 的幂，再取 `bit_length() - 1` 就还原出下标 `i`。

常见用途：判 2 的幂（`n & -n == n`）、树状数组的 `i += i & -i`、以及下面两个枚举循环。

## 4. 惯用法一：枚举集合的元素，`O(k)`

```python
t = s                       # 用副本消耗，保留原始 s
while t:
    lowbit = t & -t         # 最低位的 1 → 当前最小的元素
    t ^= lowbit             # 把它清 0（等价 t &= t - 1）
    i = lowbit.bit_length() - 1
    # 处理元素 i
```

按 `i` 从小到大访问。`t ^= lowbit` 之所以等于删位，是因为该位在 `t` 里必然是 1。

`s = 0b101100`（`{2, 3, 5}`）的执行 trace：

| 进入时 `t` | `lowbit` | 清位后 `t` | `i` |
| --- | --- | --- | --- |
| `101100` | `000100` = 4 | `101000` | 2 |
| `101000` | `001000` = 8 | `100000` | 3 |
| `100000` | `100000` = 32 | `000000` | 5 |
| `0` | 退出 | | |

对比朴素写法 `for i in range(n): if (s >> i) & 1`——那是 `O(n)`，集合稀疏时纯浪费；lowbit 版是 `O(k)`。

## 5. 惯用法二：枚举 n 个元素的全部子集，`O(2^n)`

```python
for s in range(1 << n):     # 1 << n == 2 ** n
    # 处理子集 s
```

`1 << n` 就是 `0b1` 后面跟 `n` 个 0。n 个元素每个「在/不在」，共 `2^n` 种组合；n 位二进制也刚好 `2^n` 种取值，一一对应。`n = 3` 时：

| `s` | 二进制 | 子集 |
| --- | --- | --- |
| 0 | `000` | `{}` |
| 1 | `001` | `{0}` |
| 2 | `010` | `{1}` |
| 3 | `011` | `{0,1}` |
| 4 | `100` | `{2}` |
| 5 | `101` | `{0,2}` |
| 6 | `110` | `{1,2}` |
| 7 | `111` | `{0,1,2}` |

!!! warning "遍历顺序是数值序，不是按子集大小"
    注意 `s = 4`（大小 1）排在 `s = 3`（大小 2）之后。需要按大小时靠 `s.bit_count()` 分组。
    但「子状态一定更小」这个性质是成立的：`s ^ (1 << i) < s` 恒成立，所以按数值升序遍历已经保证了 DP 的子状态先算好。

DP 数组长度也是它：`dp = [0] * (1 << n)`。这就是状压的内存天花板——`n = 20` 是百万格，`n = 25` 是三千三百万格，Python 基本到头。

## 6. 惯用法三：枚举 `s` 的所有子集，`O(2^k)`

```python
sub = s                     # 从最大的子集开始
while sub:                  # 只跑非空子集
    # 处理 sub
    sub = (sub - 1) & s     # 下一个更小的、仍是 s 的子集
```

关键是最后一行，两步：

1. **`sub - 1`**：借位使最低位的 1 变 0，它右边的所有 0 全变 1（`1011000 - 1 = 1010111`）。
2. **`& s`**：`sub - 1` 填出来的 1 可能落在 `s` 没置位的位置上（非法元素），`& s` 一次性抹掉，结果恰好是 `s` 的、比当前小的最大子集。

`s = 0b1011`（元素 `{0,1,3}`，应有 7 个非空子集）：

| `sub` | 子集 | `sub - 1` | `(sub-1) & s` |
| --- | --- | --- | --- |
| `1011` = 11 | `{0,1,3}` | 10 | **10** |
| `1010` = 10 | `{1,3}` | 9 | **9** |
| `1001` = 9 | `{0,3}` | 8 | **8** |
| `1000` = 8 | `{3}` | 7 = `0111` | **3** ← `0111` 含非法元素 2，被抹成 `0011` |
| `0011` = 3 | `{0,1}` | 2 | **2** |
| `0010` = 2 | `{1}` | 1 | **1** |
| `0001` = 1 | `{0}` | 0 | **0** → 退出 |

最后一行的 `& s` 就是它存在的意义：只写 `sub = sub - 1` 会访问到 `{2}`、`{1,2}` 这些根本不是 `s` 子集的掩码。

!!! warning "两个坑"
    - **空集被跳过**：`while sub:` 在 `sub` 归 0 时就结束。DP 里空集常是 base case，需单独处理，或改成 `while True: ...; if sub == 0: break; sub = (sub - 1) & s`。
    - **顺序是数值递减**，不是按大小分层。

!!! info "总复杂度是 3^n 不是 4^n"
    外层 `for s in range(1 << n)` 跑 `2^n` 次，内层对每个 `s` 跑 `2^popcount(s)` 次。求和时每个元素有三种状态（不在 `s` 里 / 在 `s` 里但不在 `sub` 里 / 两者都在），故总计 `3^n`。`n = 20` 约 34 亿次，Python 跑不完，C/Zig 也要几秒。

## 7. 例题一：统计二进制位全部相同的数

> 求 `[0, n]` 中「二进制所有位都相同」的整数个数。

**第一步，给满足性质的数找参数化双射。** 二进制表示不写前导零，所以「所有位相同」只有两种可能：全 0（即 `x = 0`）或全 1。全 1 就是 `1, 11, 111, ...`，即 `x = 2^k - 1`。而 `k = 0` 时 `2^0 - 1 = 0` 正好把全 0 那种也吸收了。于是：

> 满足条件的 `x` 与非负整数 `k` 一一对应，`x = 2^k - 1`。

问题从「逐个检查 0..n」退化成「数 `k` 能取几个值」。

**第二步，解不等式。**

```
0 <= 2^k - 1 <= n   ⟺   1 <= 2^k <= n + 1   ⟺   k <= floor(log2(n + 1))
```

而 `bit_length()` 的定义正是 `floor(log2(m)) + 1`，故 `k` 的范围是 `0 .. (n+1).bit_length() - 1`，共 `(n+1).bit_length()` 个。

```python
class Solution:
    def countMonobit(self, n: int) -> int:
        return (n + 1).bit_length()
```

验证：`n = 7` → `0, 1, 3, 7` 共 4 个，`(7+1).bit_length()` = `0b1000` 的长度 = 4 ✓

!!! question "为什么是 `n + 1` 而不是 `n`"
    边界。`n = 7` 时 `7.bit_length()` 也是 4，碰巧对；但 `n = 8` 时答案仍是 4（`15 > 8`），而 `8.bit_length()` = 5，错了。`n + 1` 让 `2^k` 的临界点落在正确一侧。这种 off-by-one 只能靠推不等式确定，靠试几个样例不可靠。

## 8. 例题二：严格回文的数字

> 若 `n` 在所有进制 `b`（`2 <= b <= n - 2`）下的表示都是回文，称其严格回文。判断给定 `n` 是否严格回文。

答案是**恒为 `False`**（题目约束 `6 <= n <= 10^5`）。要推翻「所有进制都回文」只需构造**一个**反例进制，取 `b = n - 2`：

```
n = 1·b + 2        因为 1·(n-2) + 2 = n
```

余数 2 合法要求 `2 < b`，即 `n > 4`；再验证它确实只有两位（需 `n < b²`）：

```
n < (n-2)²  ⟺  0 < n² - 5n + 4 = (n-1)(n-4)  ⟺  n > 4   ✓
```

所以 `n > 4` 时 `n` 在基 `n-2` 下的表示**恰好是两位数 `12`**，而两位数是回文 ⟺ 首位 = 末位 ⟺ `1 == 2`，永不成立。

剩下的手工查：`n = 4` 时基 2 得 `100`，不是回文；`n <= 3` 时 `2 > n - 2`，待检查的进制集合为空，定义上「所有进制都回文」空真为 `True`——但被题目约束排除了。

```python
class Solution:
    def isStrictlyPalindromic(self, n: int) -> bool:
        return False
```

!!! tip "选进制的手感"
    取 `b = n - k` 能让商和余数都变成小常数，是进制类构造题的常用套路。注意 `b = n - 1` 会得到 `11`，那**是**回文，所以要害在 `n - 2`。

## 9. 迁移到工程时的差异

把这套 Python 代码译成 Zig / C 时，会踩的点全在语言语义差异上，而不在算法：

- **Python 整数是任意精度**，`1 << n` 再大也不溢出；定宽整数下 `u64` 只能到 `n = 63`，`1 << n` 在 C 里还要求左操作数是 `unsigned`，否则移位有符号数是 UB。
- **`-n` 的补码语义**在定宽下依然成立，但 `n = 0` 时 `(n & -n).bit_length() - 1` 返回 `-1` 当哨兵，在无符号类型里会变成最大值。
- **`n & -n` 在 x86 上有单条指令** `blsr`/`tzcnt`，Zig 里直接用 `@ctz(n)`，比手写 lowbit 更快也更清楚。

!!! note "练题的落点"
    真正能迁移的是复杂度直觉（看到 `O(n·2^n)` 就知道 `n = 20` 是天花板）、位图这类数据结构的选型，以及边界条件的肌肉记忆。竞赛式的数学 trick 本身用处有限，但「先做双射再计数」这种化归思路是通用的。
