# AI 时代代码表达的真正核心

> 它们比纠结注释重要 10000000 倍。

传统软件工程强调"写注释是美德"。但在 AI/LLM 时代，注释是最脆弱的知识载体：人会忘改、AI 会忽略、测试不会验证它。真正经得起时间冲刷、且 AI 代理能可靠消费的，是下面这四样东西。

---

## 一、SOP/*.md — 标准操作流程文档

`SOP = Standard Operating Procedure`

每项重复性工作都应该沉淀为标准流程文档。它不是"设计文档"那种一次性产物，而是**活文档**，每次执行时被阅读、被修正、被验证。

### 为什么比注释重要
| 维度 | 代码注释 | SOP 文档 |
|------|---------|---------|
| 受众 | 人类开发者 | 人类 + AI 代理 |
| 验证 | 无强制验证 | 执行即验证 |
| 时效 | 常过时 | 不过时就执行不下去 |
| 粒度 | 函数/模块级 | 工作流级 |

```
SOP/
├── release.md        # 发布流程
├── incident.md       # 故障响应
├── onboarding.md     # 新人接入
├── code-review.md    # 代码审查
└── deploy-rollback.md # 部署与回滚
```

## 二、AGENTS.md + README.md — 项目的第一入口

`AGENTS.md` 是写给 AI 代理看的项目说明书。`README.md` 是写给人看的入口。两者共同构成一个项目的"接口契约"。

### AGENTS.md 的标准写法
- 项目定位：一句话说明这个项目做什么；
- 技术栈 + 目录结构；
- 开发规范（lint/format/test 命令）；
- 常见任务模式（如何加一个新接口、如何写迁移等）；
- 约束与红线（不可做的事）。

### 为什么比注释重要
AI 代理进入一个陌生仓库，第一件事就是找 `AGENTS.md`（或 `.cursorrules` / `CLAUDE.md`）。没有它，代理在黑暗里摸索；没有注释，代理还能靠代码+测试推断。**注释解释代码，AGENTS.md 却定义边界。**

## 三、tests/ + 自描述代码

### 测试是唯一不可说谎的文档

注释会骗人，测试不会——测试要么通过，要么失败。它是**可执行规范**：

- **单元测试** = 函数的输入输出契约；
- **集成测试** = 模块间协作的真实约定；
- **端到端测试** = 用户行为的可执行描述。

### 自描述 + 上下文无关

代码本身要让意图透明，不依赖额外注释才能读懂：

#### 变量（自描述）
```python
# ❌
d = calc(a, b, 0.85)  # 计算折扣

# ✅
final_price = calculate_discounted_price(base_price, tax_rate, discount_percentage=0.85)
```

#### 函数（上下文无关）
```python
# ❌ 读这个函数需要先去理解 state 是什么
def process(state):
    ...

# ✅ 输入输出完全自包含
def create_order_item(user_id: UUID, product_sku: str, quantity: int) -> OrderItem:
    ...
```

#### 文件（自描述）
```
❌ utils.py, helpers.py, common.py
✅ price_calculator.py, token_counter.py, pdf_parser.py
```

AI 代理理解自描述代码的效率远高于阅读注释——因为变量名和函数签名本身就是类型系统能验证的元数据。

## 四、Wiki — 团队知识库

Wiki 不是代码仓库的附属品，而是团队认知的**唯一真实来源**：

- 架构决策记录（ADR）；
- 业务领域术语表；
- 历史故障复盘；
- 技术选型理由；
- 常见问题（FAQ）。

### 为什么比注释重要
注释解释"这段代码在做什么"——Wiki 解释"我们为什么这样做"。**前者回答 How，后者回答 Why + Context。** AI 代理需要 Why 才能给出靠谱建议，而注释写不了 Why。

---

## 总结

```
代码注释         →  给人类读的即时提示，易腐、不可验证
SOP/*.md        →  可执行的工作流，人类和 AI 共同的行动手册
AGENTS.md       →  AI 代理的项目说明书
README.md       →  人类开发者的项目入口
tests/          →  不可说谎的可执行规范
自描述代码       →  意图内化在命名与类型中，无需注释补充
Wiki            →  团队的 Why & Context，认知的唯一来源
```

**一句话：让代码自己说话，让文档定义边界，让测试验证一切。注释只是最后的补充，不是第一道防线。**
